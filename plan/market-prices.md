# 실제 시세를 게임에 들이기

지금 앱은 카드 값을 **등급 하나로만** 매긴다. 팩은 세트와 상관없이 전부 1,000만이고, 카드를
갈면 등급별 고정 표에서 값이 나온다. 실제 시장은 그렇지 않다. 이 문서는 얼마나 다른지 재고,
바꾼다면 무엇이 무너지고 무엇이 생기는지 정리한다.

조사 대상은 사용자가 준 [collectory.cc](https://collectory.cc/)와, 우리가 이미 카드 데이터를
받고 있는 `api.pokemontcg.io` 두 곳이다.

## 1. 도메인 — 포켓몬 카드 값은 무엇으로 정해지는가

우리 앱에 실린 1,284장의 실제 시세를 받아 확인했다(2026-08-30 기준, 1,283장 확보).

### 등급은 값의 순서를 알려 주지 않는다

등급별 중앙값을 낮은 등급부터 늘어놓으면 네 군데서 뒤집힌다.

| 등급 | 중앙값 | |
|---|---:|---|
| C | $0.31 | |
| U | $0.35 | |
| R | $0.56 | |
| RR | $2.33 | |
| RRR | $1.59 | ← RR 보다 싸다 |
| AR | $14.36 | |
| SR | $3.75 | ← AR 보다 싸다 |
| SAR | $55.98 | |
| UR | $9.29 | ← AR·SAR 보다 싸다 |

우리 앱은 UR 을 최상위로 두고 분해값 3,000만(최고액)을 준다. 시장에서 UR 중앙값은 SAR 의
**6분의 1**이다. 등급 사다리와 값 사다리가 애초에 다른 축이다.

### 같은 세트·같은 등급 안에서도 수십 배가 벌어진다

인기가 값을 만든다. 등급이 같아도 무엇이 그려져 있느냐가 훨씬 크게 작용한다.

| 세트·등급 | 비싼 쪽 | 싼 쪽 | 배수 |
|---|---|---|---:|
| base1 RR | 리자몽 $868.56 | 홍수몬 $20.97 | 41배 |
| sv3pt5 SAR | 리자몽 ex $370.48 | 비주기의 카리스마 $14.94 | 25배 |
| sv10 SAR | 로켓단의 뮤츠 ex $482.88 | 메가자리 ex $19.93 | 24배 |

리자몽이 세 번 중 두 번 비싼 쪽에 있다. 캐릭터 인기가 등급보다 강하게 작동한다.

### 오래된 세트는 바닥을 올리고, 최신 세트는 천장을 올린다

세트를 출시일 순으로 늘어놓으면 **평균이 아니라 중앙값**에서 규칙이 보인다.

| 세트 | 출시 | 중앙값 | 평균 | 최고가 |
|---|---|---:|---:|---:|
| base1 | 1999 | $2.51 | $21.31 | $868 |
| neo1 | 2000 | $4.91 | $44.77 | $1,085 |
| xy12 | 2016 | $1.89 | $7.88 | $125 |
| sm115 | 2019 | $0.99 | $4.90 | $73 |
| swsh45 | 2021 | $0.31 | $1.18 | $11 |
| cel25 | 2021 | $0.36 | $4.47 | $64 |
| swsh12pt5 | 2023 | $0.37 | $1.80 | $49 |
| sv3pt5 | 2023 | $0.99 | $9.75 | $370 |
| sv8pt5 | 2025 | $0.30 | $27.96 | $1,466 |
| sv10 | 2025 | $0.32 | $7.56 | $483 |

옛날 세트는 **흔한 카드까지 값이 붙는다**(중앙값 $2.51·$4.91). 25년치 소각과 훼손을 지나
남은 물량이 적기 때문이다. 반대로 최신 세트는 중앙값이 $0.30 언저리로 주저앉지만 최고가는
$1,466까지 올라간다. 물량은 넘치고 값은 소수의 치트키 카드에 몰린다.

그래서 "오래된 팩이 비싸다"는 한 문장으로는 부족하다. **오래된 팩은 안전하고, 최신 팩은
복권이다.** 이 차이가 게임에 그대로 옮길 만한 성질이다.

### 값이 한 장에 몰리는 정도

세트별로 상위 10% 카드가 전체 값의 52~91%를 차지한다. sv8pt5 는 90.6%, swsh45 는 52.3%다.
쏠림이 심한 세트일수록 팩을 여는 경험이 도박에 가까워진다.

## 2. 데이터를 어디서 얻는가

### collectory.cc — 참고는 되지만 끌어다 쓸 곳은 아니다

한국·일본·미국·중국 시세를 비교하는 국내 서비스다. 카드 개별 시세, 실거래 기록, 시세 추이
그래프, **PSA·CGC 등급별 값**, **미개봉 상품(실링) 시세**, 주간 급등락, 자체 시장 지수를
제공한다. 우리에게 특히 쓸모 있어 보이는 것은 실링 시세(팩 값을 정할 근거)와 한국 시세다.

**다만 공개 API 는 없고, 내부 API 는 쓰면 안 된다.** `/api/cards` 가 JSON 을 돌려주기는 하나
`robots.txt` 가 `Disallow: /api/` 로 명시해 자동 접근을 거부하고 있다. 남의 서비스가 모아 둔
데이터를 그 서비스의 의사에 반해 긁어 오는 일이라 여기서는 하지 않는다.

### api.pokemontcg.io — 이미 쓰고 있고, 시세가 들어 있다

카드 데이터를 받는 그 API 가 카드마다 시세를 함께 준다. 따로 붙일 것이 없다.

- **TCGplayer**(미국·달러): 판본별(노멀·리버스·홀로) low/mid/high/market
- **Cardmarket**(유럽·유로): trendPrice, 30일 평균 등
- 갱신: 날마다. 확인 시점의 값이 전날 날짜로 찍혀 있었다
- 우리 카드 1,284장 중 **1,283장에 값이 있다**

없는 것은 실링 시세와 등급(PSA) 시세, 한국 시세다. 우리 게임에는 개별 카드 값만 있어도
충분하고, 팩 값은 아래처럼 계산으로 만들 수 있다.

## 3. 게임에 넣으면 무엇이 뒤집히는가

### 지금 팩 값은 최대 53배 틀려 있다

우리 팩 구성(4+3+2+1칸, 칸마다 등급 가중치)에 실제 시세를 넣어 팩 하나의 기대값을 계산했다.

| 세트 | 팩 기대값 | 현재 팩값 | 배수 |
|---|---:|---:|---:|
| neo1 | $177.10 | 1,000만 | **53.5x** |
| base1 | $88.73 | 1,000만 | 26.8x |
| xy12 | $23.07 | 1,000만 | 7.0x |
| sm115 | $17.24 | 1,000만 | 5.2x |
| sv3pt5 | $15.56 | 1,000만 | 4.7x |
| cel25 | $7.22 | 1,000만 | 2.2x |
| sv10 | $6.67 | 1,000만 | 2.0x |
| sv8pt5 | $5.98 | 1,000만 | 1.8x |
| swsh12pt5 | $5.52 | 1,000만 | 1.7x |
| swsh45 | $3.31 | 1,000만 | 1.0x |

전부 같은 값에 판다. 시세를 들이는 순간 **네오 제네시스만 사는 것이 유일한 정답**이 된다.
다른 아홉 세트를 살 이유가 사라진다. 팩 값을 손보지 않고 시세만 넣으면 게임이 그날로 끝난다.

### 그래서 바뀌어야 하는 것

**팩 값을 기대값에 연동한다.** `팩값 = 기대값 × 환율 × 마진`. 마진이 모든 세트에 같으면 어느
세트를 사도 기대 수익률이 같아지고, 선택의 기준이 수익률이 아니라 **성향**이 된다 — 바닥이
높은 옛날 팩이냐, 천장이 높은 최신 팩이냐.

환율은 지금 감각을 유지하도록 잡는다. 구체적인 값과 세트별 결과는 4절에 있다. 양 끝만
미리 적으면 샤이닝 페이츠 약 290만, 네오 제네시스 약 1억 5,500만이다.

53배 격차를 곡선으로 눌러 완화하고 싶어지는데, 그렇게 하면 안 된다. 이유는 4절에서 따로
다룬다 — 누르는 순간 비싼 세트의 수익률이 오히려 높아져 지금과 같은 문제로 되돌아간다.

**분해값을 등급표에서 카드 시세로 바꾼다.** 지금 등급표는 시장과 네 군데서 순서가 뒤집혀
있다. 카드마다 값을 매기면 같은 SAR 이라도 리자몽과 그렇지 않은 것이 25배 차이가 나고,
"무엇을 뽑았는가" 가 처음으로 등급 배지 말고 숫자로도 의미를 갖는다.

**경제 불변식을 다시 세워야 한다.** 지금 규칙은 "팩을 갈아 나오는 총액이 팩 값을 넘지
않는다"(현재 약 3분의 1)이다. 카드값과 팩값이 모두 시세에서 나오면 이 비율은 **마진 하나로**
결정되므로 오히려 관리하기 쉬워진다. 다만 도감 혜택(분해 +6%, 팩 할인 10%)이 이 비율을
갉아먹는 계산은 새 값으로 다시 해야 한다.

**오리파 구성도 다시 봐야 한다.** 지금은 등급만 보고 100칸을 채운다(UR 1, SAR 4, …).
등급이 값을 뜻하지 않으므로, 시세 기준으로 채우지 않으면 "비싼 등급이 들었는데 싼 박스" 가
나온다.

### 새로 생기는 것

**컬렉션에 시세가 붙는다.** 모은 카드의 총 평가액이 생기고, 그것이 날마다 움직인다. 지금
컬렉션 탭은 "몇 장 모았나" 만 말하는데, "얼마어치를 갖고 있나" 가 붙으면 모으는 이유가 하나
늘어난다. 값이 오른 카드·내린 카드를 보여 주는 화면은 그 자체로 볼거리가 된다.

**치트키 카드가 진짜 치트키가 된다.** 지금은 UR 을 뽑으나 SAR 을 뽑으나 분해값 차이뿐이다.
시세를 넣으면 sv8pt5 에서 $1,466짜리 한 장을 뽑는 사건이 생긴다. 그 세트 전체 값의 29%가
그 한 장에 있다.

### 조심할 것

**시세가 날마다 움직이면 경제가 발밑에서 흔들린다.** 자던 사이에 팩값이 오르고 갖고 있던
카드의 분해값이 떨어지는 게임은 불쾌하다. **버전마다 시세 스냅샷을 번들에 넣어 고정하고,
업데이트가 곧 「시세 갱신」 이벤트가 되게** 하는 편이 낫다. 그러면 값이 바뀌는 시점이 명확하고,
패치 노트에 "이번 주 급등 카드" 를 적을 수도 있다. 지금 카드 목록·한국어 이름을 번들로
배포하는 방식과도 같다.

**세트별 난이도 차이가 도감을 덮친다.** 도감 난이도는 팩 확률에서 계산하는데, 팩값이 세트마다
달라지면 "완성에 필요한 팩 수" 가 아니라 "완성에 드는 토큰" 으로 재는 편이 맞다.

**환율 한 줄이 게임 전체를 좌우한다.** 달러를 토큰으로 옮기는 계수 하나가 팩값·분해값·오리파
값에 동시에 걸린다. 한곳에 두고 테스트로 묶어야 한다.

## 4. 맞추는 계획

### 값을 만드는 식

두 상수만 둔다. 나머지는 전부 여기서 나온다.

```
분해값(카드) = 시세 × RATE
팩값(세트)   = 팩 기대값(세트) × RATE × MARGIN
```

`MARGIN` 은 팩을 사서 갈기만 할 때의 손실률을 정한다. 지금 게임이 그 비율을 3 으로 잡고
있으므로(팩 1,000만 대 기대 환급 330만) `MARGIN = 3` 이면 체감이 그대로 유지된다.

`RATE` 는 달러를 토큰으로 옮기는 계수다. 세트별 기대값의 중앙값이 $11.4 이므로 1달러당
약 29만 토큰으로 두면 중간 세트 팩이 지금과 같은 1,000만 언저리에 남는다.

이 식의 좋은 점은 **어느 세트를 사도 기대 수익률이 같아진다**는 것이다. `MARGIN` 이 모든
세트에 같으므로 "무엇이 이득인가" 라는 질문이 사라지고, 대신 성향을 고르게 된다.

### 격차를 누르면 안 된다

앞 절에서 `기대값^0.7` 로 눌러 53배를 20배로 줄이는 안을 적었는데, **그건 틀렸다.**
팩값이 기대값보다 느리게 오르면 비싼 세트의 수익률이 오히려 높아진다.

```
기대값/팩값 = 기대값 / (k · 기대값^0.7) = 기대값^0.3 / k
```

네오 제네시스는 $177^0.3 = 4.71, 샤이닝 페이츠는 $3.31^0.3 = 1.44 이므로 토큰당 3.3배를
더 돌려받는다. 누르는 순간 다시 한 세트만 사는 게임이 된다. 지불 능력이 걱정이면 팩값이
아니라 **적립 속도나 보너스 팩**으로 풀어야 한다.

베이스 세트와 네오 제네시스가 며칠치 코딩을 모아야 하는 목표가 된다. 그게 "단종팩" 이다.

### 순서

**1단계 — 시세를 앱에 들인다.** (이번에 완료)
번들 스냅샷(`card-prices.json`)과 `CardPrices`, 카드 상세의 시세 표시까지. 경제는 아직
건드리지 않는다. 값이 눈에 보이기 시작하는 것만으로 다음 단계의 근거가 쌓인다.

**2단계 — 분해값을 시세로 바꾼다.**
`CardDust` 의 등급표를 `시세 × RATE` 로 갈아 끼운다. 등급표가 시장과 네 군데 뒤집혀 있으므로
여기서 체감이 가장 크게 달라진다. 팩값은 아직 그대로 두고, 회수율이 어떻게 변하는지 먼저 잰다.

**3단계 — 팩값을 세트별로 매긴다.**
팩 기대값을 계산해 `PackPricing` 에 넣는다. 기대값은 팩 구성과 세트 풀에서 나오므로 앱 안에서
계산할 수 있다 — 미리 계산해 넣으면 팩 구성을 손볼 때마다 어긋난다.

**4단계 — 딸려 오는 것들.**
오리파 100칸을 시세 기준으로 채우고, 도감 난이도를 "팩 수" 가 아니라 "토큰" 으로 다시 잰다.
도감 혜택(분해 +6%·팩 할인 10%)이 새 회수율을 얼마나 갉는지도 다시 계산한다.

**5단계 — 컬렉션 평가액.**
모은 카드의 총액과, 갱신 때 오르내린 카드를 보여 준다. 여기서부터는 새 기능이라 위 네 단계와
분리해도 된다.

1~3 은 한 덩어리로 봐야 한다. 분해값만 바꾸고 팩값을 두면 옛날 팩이 노다지가 된다.

### 지켜야 할 것

- **회수율.** 팩을 사서 갈기만 할 때 돌아오는 비율이 `1/MARGIN` 을 넘지 않아야 한다.
  도감 혜택을 최대로 켠 상태에서도 마찬가지다. 지금 테스트가 이 불변식을 지키고 있으므로

- **환율은 한곳에.** `RATE` 하나가 팩값·분해값·오리파값에 동시에 걸린다.
