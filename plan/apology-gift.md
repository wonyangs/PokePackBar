# 사죄의 사료 — 한 번만 주는 보상

v0.4.0 에서 값을 반올림해 보여 준 탓에 적힌 값과 실제로 빠지는 값이 달랐다. 살 수 있다고
나오는 팩을 못 사고, 사고 나면 남은 돈이 계산과 맞지 않았다. 그 사과로 v0.4.1 을 처음 열 때
한 번 보상을 준다. 이 문서는 **무엇을 얼마나** 줄지와 **어떻게 한 번만** 줄지를 정한다.

## 1. 무엇을 주는가

| | 값 |
|---|---:|
| 세트마다 팩 1개 (10종) | 1,292,800원 |
| 현금 | 1,000,000원 (212,120,000 토큰) |
| **합계** | **2,292,800원** |

현금을 **원으로 적는다.** 요청은 2억 토큰이었는데 그대로 두면 942,900원이라는 어정쩡한 값이
나온다. 화면 단위가 원이므로 100만원으로 끊는 편이 읽기 좋고, 토큰으로는 2억 1,212만이라
요청한 규모와 같다.

세트마다 1팩은 값으로 보면 한쪽으로 크게 기운다 — Neo Genesis 한 팩이 61만원, Shining Fates
는 1만 3천원이다. 그래도 **종류별 1팩**이 맞다. 값을 맞추려고 개수를 조절하면 싼 세트만
수십 개가 되어 뜯는 것이 일이 되고(한번에 판매를 만든 이유와 같다), 이 보상의 뜻은 「모든 팩을
한 번씩 열어 보라」는 쪽이다.

합계 229만원은 팩 값으로 치면 최신 세트 기준 70팩 남짓이다. 경제를 흔들 규모는 아니다.

## 2. 누가 받는가

**이미 팩을 사 본 세이브만** 받는다. `packsOpened > 0` 이거나 `spentTokens > 0` 인 경우다.

v0.4.1 을 처음 설치하는 사람은 겪지도 않은 일로 229만원을 들고 시작하게 되고, 그러면 초반에
무엇을 살지 고르는 재미가 통째로 사라진다. 사과는 겪은 사람에게 한다.

## 3. 어떻게 한 번만 주는가

### 세이브에 지급 기록을 남긴다

```swift
// GameState
/// 이미 준 일회성 보상의 id. 한 번 준 것을 다시 주지 않으려는 것이다.
var grantedGifts: [String] = []
```

버전 번호가 아니라 **보상 id** 로 기록한다(`"v0.4.1-apology"`). 버전으로 기록하면 다음에
다른 이유로 또 줄 때 같은 칸을 두고 다투게 된다. id 목록이면 보상을 여러 번 만들어도
각자 한 번씩만 나간다.

### 지급

```swift
// WalletStore
struct Gift: Sendable {
    let id: String
    let tokens: Int
    let packsPerSet: Int
}

/// 준 적이 없고 대상이면 준다. 이미 줬으면 아무것도 하지 않는다.
@discardableResult
func claim(_ gift: Gift, index: CardIndex?) -> Bool
```

- `state.grantedGifts.contains(gift.id)` 면 즉시 `false`
- 대상이 아니면 id 만 기록하고 `false` — **기록은 남긴다.** 안 남기면 나중에 팩을 하나 사는
  순간 대상이 되어 뒤늦게 지급된다
- `state.perkTokens += gift.tokens` (사용량 통계를 건드리지 않고 잔액만 올리는 칸이다)
- 세트마다 `state.packs[setID] += gift.packsPerSet`
- id 를 기록하고 **한 번만** 저장

### 언제 부르는가

앱을 띄울 때 `WalletStore` 를 만든 직후, 카드 인덱스가 준비된 시점에 부른다. 팝오버를 열 때
부르면 팝오버를 안 여는 동안 팩이 안 들어와 있다.

## 4. 어떻게 알리는가

보너스 팩 안내(`lastGrant`)와 같은 방식으로 팝오버 위쪽에 한 번 띄우고 닫으면 사라진다.
새 문구가 아니라 새 종류의 알림이 필요하다 — 보너스 팩 안내는 「어느 한도를 채워서 무슨 팩을
몇 개 받았다」는 문장이라 이 보상에 맞지 않는다.

```
🍚 사죄의 사료
   값이 잘못 보이던 문제로 불편을 드렸습니다.
   팩 10개와 1,000,000원을 넣어 뒀어요.                    [닫기]
```

**받은 것을 숫자로 적는다.** 「보상을 드렸습니다」만 있으면 무엇이 들어왔는지 확인하려고
탭을 뒤져야 한다.

## 5. 테스트로 잠글 것

- 두 번 불러도 한 번만 들어온다 (잔액·팩 수가 그대로)
- 대상이 아닌 세이브는 받지 않지만 **기록은 남는다** (나중에 팩을 사도 다시 안 들어온다)
- 잔액이 정확히 `tokens` 만큼 오르고 `usedSinceInstall` 은 그대로다 (통계를 건드리지 않는다)
- 세트마다 정확히 1팩씩 들어온다
- 다른 id 의 보상은 따로 한 번씩 나간다
- 저장이 한 번만 일어난다

## 6. 하지 않을 것

**소급 정산.** 「반올림 때문에 실제로 얼마를 손해 봤는지」를 세이브에서 되짚어 그만큼 주는
방식이다. 지출 기록에 당시 표시값이 남아 있지 않아 계산할 수 없고, 계산할 수 있더라도 사람마다
다른 액수가 나와 「나는 왜 적게 받았나」가 된다. 정액이 낫다.

**보상 반복 지급.** 다음 버전에서 또 주고 싶으면 새 id 로 새 보상을 만든다. 같은 id 를 다시
열지 않는다.
