# 메뉴바에 최애 카드 띄우기

메뉴바 아이콘을 고정 기호에서 **내 카드**로 바꾼다. 최애 카드를 지정하면 그것을, 지정하지
않았으면 가진 것 중 가장 높은 등급을, 아무 카드도 없으면 지금 쓰는 카드 묶음 기호를 쓴다.

## 왜 하는가

지금 메뉴바에는 `rectangle.stack.fill` 기호가 늘 같은 모습으로 붙어 있다. 팩을 뜯어 좋은
카드를 얻어도 화면에 남는 흔적이 없다. 뽑은 카드가 하루 종일 눈에 보이면 팩을 여는 이유가
하나 더 생긴다.

## 무엇을 보여 주는가

**카드를 자르지 않고 통째로 줄인다.** 메뉴바 두께(22pt)에서 카드 높이 18pt, 가로는 비율대로
13pt 남짓이 된다. 그 안의 포켓몬은 작지만, 어떤 카드에서도 늘 카드로 보인다.

그림 창만 잘라 내면 포켓몬은 크게 보인다. 실제 이미지로 확인해 보니 자르는 위치를 판형마다
따로 정해야 했다 — 최신 일반 카드는 세로 9~46%가 그림 창이지만, 1999년 베이스 세트는 창이
더 아래에서 시작해 같은 값을 쓰면 카드 이름줄이 딸려 들어오고, 풀아트 카드는 전면이 그림이라
잘라 낼 창 자체가 없다. 세트별 표를 두고 관리하는 비용에 비해 얻는 것이 크지 않아 버렸다.

세로는 메뉴바 두께에 맞춰 고정하고 가로만 비율대로 둔다. 세로가 카드마다 흔들리면 옆의
사용량 숫자와 밑선이 어긋난다. 설정에 지금 무엇이 올라가 있는지 보여 주는 줄을 둔다.

## 어떤 카드가 뽑히는가

```
최애 카드(지정했고 아직 갖고 있다)  →  가진 것 중 가장 높은 등급  →  기존 기호
```

- 최애가 손에 없으면 자동 선택으로 내려간다. 갈아 없애기는 마지막 한 장을 남기므로 이 경우는
  보통 생기지 않지만, 세이브를 손으로 고쳤거나 카드 목록이 바뀌어 그 ID 가 사라진 상황에서도
  메뉴바가 비지 않게 해 둔다.
- 같은 등급이 여럿이면 **세트 출시일이 최신인 것 → 세트 ID → 카드 번호가 앞인 것** 순으로
  고른다. 뽑은 순서를 쓰는 편이 더 자연스럽지만 획득 시각을 저장하고 있지 않고, 그 값을
  남기려면 세이브 구조를 건드려야 한다. 규칙으로 고정하면 같은 보유 상태에서 항상 같은
  카드가 나온다 — 켤 때마다 아이콘이 바뀌면 고장으로 보인다.
- 기본 에너지(E)는 후보에서 뺀다. 메뉴바에 에너지 카드가 올라오면 상이 아니라 잡음이다.

## 손댈 곳

**저장** — `GameState.favoriteCardID: String?`. 세이브 파일에 들어가는 게임 상태이므로
`UsageStore`(환경 설정)가 아니라 여기가 맞다. 예전 세이브에는 없는 항목이라 옵셔널로 둔다.

**결정 로직** — `Core/MenuBarCard.swift` 에 순수 함수로 둔다.
`resolve(favorite:owned:index:) -> CardEntry?`. 입력이 전부 값이라 테스트가 쉽다.

**이미지 합성** — `Core/MenuBarCardImage.swift`.
기하 계산(`layout(for:thickness:)`)을 순수 함수로 떼어 테스트한다. 합성은 걷어낸 companion 의
`menuBarLayout` 방식을 그대로 쓴다 — 세로를 두께에 고정하고 가로는 비율대로, Retina 는
`lockFocus` 가 2배로 그린다. 모서리만 살짝 깎아 작아도 카드로 읽히게 한다.

**표시** — `PokePackBarApp.swift`. 지금 `menuIcon()` 이 반환하는 기호 자리에 카드 이미지를
넣는다. 이미지 교체는 이미 있는 `setStatusImage` 를 그대로 탄다(같은 이미지면 건너뛰고 CA
전환을 끈다). `observeStore` 옆에 지갑 관찰을 하나 더 걸어 보유 카드나 최애가 바뀌면 다시
계산한다.

**지정하기** — 카드 확대 화면(`CardSpotlightView`) 왼쪽 위에 별 버튼을 붙인다. 카드를
들여다보는 자리가 최애를 정하는 자리다. 가진 카드에만 준다.

**설정** — 메뉴바 섹션에 「메뉴바에 카드 표시」 토글과, 지금 올라가 있는 카드 한 줄을 둔다.
자동으로 뽑힌 것이면 「가장 높은 등급 (자동)」이라고 적고, 직접 정한 것이면 해제 버튼을 준다.
토글을 끄면 기존 기호로 돌아간다 — 메뉴바는 좁아서 취향이 갈리는 자리다.

## 이미지를 언제 얻는가

카드 이미지는 번들에 없다. Supabase 에서 받아 Application Support 에 캐시한다.

- 앱을 켤 때 캐시에 있으면 동기로 읽어 바로 붙인다(`CardImageLoader.cachedImage`).
- 없으면 기존 기호로 시작하고, 받아 온 뒤 바꿔 끼운다. 한 번 깜빡이지만 캐시가 채워진
  뒤에는 다시 일어나지 않는다.
- 최애로 지정할 수 있는 카드는 **이미 뽑아 본 카드**뿐이라 대개 캐시에 있다.

## 하지 않는 것

**움직이지 않는다.** 이전 companion 의 메뉴바 스프라이트는 프레임마다 이미지를 갈아 끼워
CA 커밋을 일으켰고, idle CPU 의 주범으로 지목돼 걷어냈다. 같은 것을 다시 들이지 않는다.
정지 이미지 한 장이면 화면 갱신이 아예 없다.

**포켓몬 스프라이트를 새로 받아오지 않는다.** PokéAPI 스프라이트를 쓰면 작게 보기엔 더
또렷하지만, 트레이너·에너지 카드에는 대응이 없고 걷어낸 PokéAPI 경로를 되살려야 한다.
이 기능의 주인공은 포켓몬이 아니라 내가 뽑은 카드다.

## 테스트

- 최애 → 최고 등급 → nil 순서로 내려가는가
- 갖고 있지 않은 최애·목록에 없는 최애가 자동 선택으로 내려가는가
- 같은 등급이 여럿일 때 항상 같은 카드가 뽑히는가
- 합성한 카드가 캔버스를 넘지 않는가(두께 20·22·24·26)
- 세로가 두께에 고정되고 원본 비율을 지키는가 — 걷어낸 `SpriteAspectRatioTests` 와 같은 성격
- 세로 0 인 이미지가 들어와도 0 으로 나누지 않는가
- 에너지 카드만 가진 상태에서 기호로 남는가
- 합성 결과가 템플릿이 아닌가 — 템플릿이면 메뉴바가 단색으로 칠해 그림이 사라진다

## 구현 결과

전부 반영했다. `MenuBarCardTests` 16개가 규칙과 기하를 지킨다.

부수적으로 번들 카드 인덱스를 `CardIndex.shared` 하나로 모았다. 팝오버·보너스 팩·메뉴바가
각자 `loadBundled()` 를 부르고 있어 같은 JSON 을 세 번 파싱하던 것을 한 번으로 줄였다.

### 성능에서 조심한 곳

메뉴바 아이콘은 `applyState()`(사용량 숫자가 바뀔 때마다 호출된다)에서 다시 만들지 않는다.
합성한 `NSImage` 는 매번 새 객체라 `setStatusImage` 의 diff-gate 를 그냥 통과하고, 통과하면
CA 커밋이 한 번 돌아 idle wakeup 이 된다. 그래서 `카드ID@두께` 를 키로 들고 있다가 키가
바뀔 때만 합성한다. 카드 선택 자체도 `withObservationTracking` 으로 지갑이 바뀔 때만 다시
계산한다.
