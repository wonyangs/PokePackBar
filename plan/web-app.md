# 웹앱 (PWA)

브라우저에서 도는 두 번째 클라이언트를 만든다. **토큰을 버는 것만 빼고 전부 할 수 있다** —
팩을 사고 열고, 카드를 팔고, 오리파를 돌리고, 도감을 수령한다.

만들 자리는 `pokemon-card/web`. 서버 API 명세는 [server-api.md](server-api.md) 에 있다.

## 0. 왜 지금 만드나

서버가 상태를 전부 갖게 되면서 **앱이 상태의 주인이 아니게 됐다.** 그러면 클라이언트가 하나일
이유도 없다. 웹앱은 그 설계가 실제로 성립하는지 확인하는 가장 빠른 방법이다 — 맥 앱을 고치지
않고도 서버 API 전부를 실제 화면으로 두드려 볼 수 있다.

토큰 수급만 빠지는 이유는 단순하다. 브라우저는 사용자 Mac 의 로그 파일을 못 읽는다.
그것만 맥 앱의 몫으로 남고, 나머지는 웹에서 다 된다.

## 1. 로그인 — 구글 계정 하나가 두 클라이언트를 잇는다

**계정의 기준은 구글 계정이다.** 웹앱에서 구글로 로그인하고, 맥 앱 설정에도 「구글 로그인」을
두어 같은 계정을 고르면, 두 화면이 같은 지갑과 같은 컬렉션을 본다.

지금 `POST /v1/auth/apple` 은 **받은 문자열을 그대로 사용자 id 로 쓴다.** 서명도 발급자도
검사하지 않으므로, 남의 계정 이름만 알면 그 지갑이 열린다. 집 안에서만 쓰는 동안에는 드러나지
않지만 웹앱을 도메인에 붙이는 순간 그대로 구멍이 된다. 구글 로그인은 이것을 대체한다.

### 서버가 하는 일

```
POST /v1/auth/google   { "idToken": "<Google ID token>" }
→ { "session": "…", "expiresAt": …, "userID": "u_…", "isNew": true }
```

- 구글 공개키(JWKS)로 **서명을 검증한다.** 발급자·대상(`aud`, 우리 클라이언트 ID)·만료도 본다
- `sub` 클레임이 계정의 열쇠다. 이메일은 바뀔 수 있으므로 표시용으로만 쓴다
- 검증에 `google-auth` 를 쓴다. 공식 구현이고 공개키 캐시를 알아서 한다

### 계정 표를 고친다

지금은 `users.apple_sub` 한 칸이다. 제공자가 둘이 되므로 갈라낸다.

```sql
CREATE TABLE identities (
    provider TEXT NOT NULL,      -- 'google' | 'apple'
    subject  TEXT NOT NULL,
    user_id  TEXT NOT NULL REFERENCES users(id),
    PRIMARY KEY (provider, subject)
);
```

한 사용자가 여러 신원을 가질 수 있게 두는 것이 요점이다. 나중에 Apple 로그인을 붙여도
**같은 사용자에 신원 한 줄이 더 붙을 뿐** 계정이 갈라지지 않는다.

### 아무나 계정을 만들지 못하게 한다

구글 로그인은 전 세계 누구나 통과한다. 집 서버가 도메인에 붙어 있으면 그대로 남의 계정이
생긴다. **허용 목록을 둔다** — `POKEPACKBAR_ALLOWED_EMAILS` 에 없는 계정은 로그인을 거절한다.
비어 있으면 첫 로그인 한 명만 받고 그 뒤로는 닫는다.

### 준비물 — 이건 사람이 해야 한다

Google Cloud Console 에서 OAuth 클라이언트를 만들어야 하고, 그건 사용자 계정으로 하는 일이다.

1. 프로젝트를 만들고 **OAuth 동의 화면**을 구성한다(외부, 테스트 사용자에 본인 계정)
2. **웹 애플리케이션** 클라이언트 ID 를 만든다
   - 승인된 자바스크립트 원본: `http://localhost:8787` 과 실제 도메인
3. 맥 앱을 붙일 때 **데스크톱 앱** 클라이언트 ID 를 하나 더 만든다(루프백 리디렉션)
4. 클라이언트 ID 를 `POKEPACKBAR_GOOGLE_CLIENT_IDS` 에 쉼표로 넣는다

## 2. 서버에 더할 것

웹앱을 위해 API 를 넓히는 부분이다. 게임 규칙은 하나도 건드리지 않는다.

| 더하는 것 | 왜 |
|---|---|
| `POST /v1/auth/google` | 1절 |
| `POST /v1/dev/grant` | 웹앱은 토큰을 못 번다. 설정으로 켜고 끄는 지급 창구를 둔다 |
| `GET /v1/data/{name}` 의 로컬 배급 | 저장소가 아직 없다. 302 할 곳이 없으면 서버가 직접 내준다 |
| `/v1/manifest` 의 `economy` 블록 | 클라이언트가 값을 원으로 옮기려면 환율과 100원 칸이 필요하다 |
| `/v1/cards` 행의 `salePrice` | 판매가를 클라이언트가 계산하지 않게 한다 |
| 빌드된 웹앱을 `/` 에 붙이기 | 같은 출처라 CORS 도 없고 구글 원본도 하나로 끝난다 |

### 개발용 지급

```
POST /v1/dev/grant   { "tokens": 3000000000 }
→ { "granted": …, "revision": …, "wallet": { … } }
```

`POKEPACKBAR_DEV_GRANT=1` 일 때만 열린다. 맥 앱이 사용량을 신고하기 시작하면 끈다.
**적립이 아니라 선물로 넣는다**(`perkTokens`) — `usedSinceInstall` 은 실제 사용량이라
여기에 가짜 숫자가 섞이면 화면의 사용량 표시가 거짓이 된다.

### 값을 누가 계산하나

**실제로 빠지고 들어오는 값은 언제나 서버 응답에서 온다.** 클라이언트가 하는 계산은 표시
전용이다 — 토큰을 원으로 옮기고 100원 칸으로 끊는 두 함수뿐이고, 그 상수는 매니페스트에서
받는다. 팩값·판매가·슬롯값은 전부 서버가 준 숫자를 그대로 쓴다.

가지지 않은 카드의 시세는 `card-prices.json` 을 받아 화면에만 쓴다. 그 값으로는 아무것도
사고팔지 않으므로 규칙이 두 벌이 되지 않는다.

## 3. 화면

맥 앱의 네 탭을 그대로 따른다 — 상점 · 팩 · 컬렉션 · 도감. 같은 것을 다르게 부르면 두
화면을 오갈 때마다 다시 배워야 한다.

| 화면 | 담는 것 | 쓰는 API |
|---|---|---|
| 홈 · 지갑 | 잔액, 누적 사용량, 개봉·분해 통계 | `GET /v1/state` |
| 상점 · 일반팩 | 세트 목록(최신순), 팩값, 구매, 확률 공시, 팩 카드 라인업 | `GET /v1/packs`, `POST /v1/packs/buy`, `GET /v1/packs/{id}/odds` |
| 상점 · 오리파 | 박스 전체 공개, 남은 등급별 수, 뽑기, 박스 교체 | `GET /v1/oripa`, `POST /v1/oripa/pull`·`/replace` |
| 팩 | 보유 팩, 개봉 연출, 신규·갓팩·천장, 도감 완성 알림 | `POST /v1/packs/open` |
| 컬렉션 | 보유 카드 그리드, 정렬 4종, 세트·등급 필터, 잡카드 일괄 판매 | `GET /v1/cards`, `POST /v1/cards/sell-bulk` |
| 카드 상세 | 이미지, 시세, 최초 획득일, 판매, 즐겨찾기, 이 카드가 든 도감 | `POST /v1/cards/sell`, `PUT /v1/cards/favorite` |
| 도감 | 진행도, 어려운 것부터, 수령, 혜택 총합과 상한 | `GET /v1/dex`, `POST /v1/dex/claim` |
| 보상 | 선물·보너스 팩 알림 | `GET /v1/grants`, `POST /v1/grants/ack` |
| 설정 | 로그인·로그아웃, 언어, 캐시 비우기, 개발용 지급 | `POST /v1/auth/google` |

빠지는 것은 **사용량 신고와 메뉴바 표시**뿐이다. 둘 다 맥에서만 뜻이 있다.

### 상태를 앱에 두지 않는다는 뜻

응답이 올 때까지 버튼이 기다린다. 낙관적 갱신을 하지 않는다 — 팩을 샀는데 화면이 먼저 늘고
서버가 거절하면 되돌려야 하고, 그러면 상태의 주인이 둘이 된다.

모든 변경 응답이 `revision` 을 싣는다. 받은 판번호가 갖고 있던 것보다 크면 그 응답의 지갑을
그대로 쓰고, 아니면 `GET /v1/state` 를 다시 받는다.

## 4. 정적 데이터와 이미지

앱이 번들로 들고 있던 것을 웹앱은 받아서 캐시한다.

| 파일 | 크기 | 쓰는 곳 |
|---|---|---|
| `card-index.json` | 572KB | 카드 이름·등급·세트, 팩 라인업 |
| `card-prices.json` | 310KB | 시세 표시, 환율 |
| `card-names-ko.json` | 518KB | 한국어 카드 이름 |
| `dex.json` | 16KB | 도감 이름·구성·보상 |

첫 방문에 1.4MB 를 받고, 그 뒤로는 매니페스트의 판번호가 바뀔 때만 다시 받는다.

이미지는 API 를 타지 않는다. 매니페스트가 알려 준 주소로 브라우저가 직접 받는다.
`<cardBase>/<세트ID>/<카드ID>.webp` 한 가지뿐이다 — 저장소에 `_hires` 가 올라가 있지 않아
상세 화면도 같은 것을 쓴다.

**이미지 전송량을 조심한다.** 카드가 16,378장이고 전부 훑으면 441MB 다. `loading="lazy"` 로
화면에 들어온 것만 받고, 서비스 워커가 받은 것을 오래 잡아 둔다.

## 5. PWA 로서 무엇을 하고 무엇을 안 하나

- 홈 화면에 설치된다. 아이폰에서도 맥에서도 창 하나로 열린다
- 앱 껍데기와 정적 데이터, 한 번 본 이미지를 캐시한다. 다시 열 때 즉시 뜬다
- **오프라인에서 상태를 바꾸지 않는다.** 상태가 서버에만 있으므로 오프라인 큐도 동기화도
  두지 않는다. 연결이 없으면 컬렉션과 도감을 **읽기 전용**으로 보여 주고 그렇게 말한다

오프라인 쓰기를 넣지 않는 것이 이 설계의 값이다. 큐를 두는 순간 세이브 충돌이 돌아온다.

## 6. 구조

```
web/
  index.html
  src/
    api/        서버 호출 한 벌. 세션 헤더와 오류 코드 해석
    data/       정적 데이터 로딩과 캐시(카드 인덱스·시세·한국어 이름·도감)
    money.ts    토큰 → 원 표시. 상수는 매니페스트에서 받는다
    screens/    상점·팩·컬렉션·도감·카드 상세·설정
    ui/         카드 타일, 등급 배지, 홀로 효과, 개봉 연출
```

React + Vite + TypeScript, PWA 는 `vite-plugin-pwa`. 빌드 결과를 FastAPI 가 `/` 에 붙인다.

## 7. 순서

1. **로그인** — `identities` 표, `POST /v1/auth/google`, 허용 목록. 여기부터가 아니면
   나머지를 만들어도 열어 볼 수가 없다
2. **서버 보강** — 개발용 지급, 로컬 정적 배급, 매니페스트의 `economy`, `salePrice`
3. **웹앱 뼈대** — Vite 프로젝트, API 클라이언트, 정적 데이터 로딩, 로그인 화면
4. **상점과 팩** — 구매·개봉이 도는 것이 첫 확인 지점이다
5. **컬렉션과 카드 상세** — 판매·일괄 판매·즐겨찾기
6. **오리파와 도감** — 남은 재화 순환
7. **PWA 마감** — 매니페스트, 아이콘, 서비스 워커, 오프라인 읽기 전용
8. **맥 앱 설정에 구글 로그인** — 같은 계정으로 같은 데이터를 보는 것을 확인한다.
   이건 웹앱이 다 돈 뒤에 한다

## 8. 정한 것

- **계정의 기준은 구글 `sub` 다.** 이메일이 아니고, 신원 표로 갈라 둬 나중에 Apple 을 같은
  사용자에 붙일 수 있게 한다
- **허용 목록 없이는 열지 않는다.** 구글 로그인은 전 세계 누구나 통과한다
- **개발용 지급은 선물로 넣는다.** 사용량 표시를 거짓으로 만들지 않는다
- **낙관적 갱신을 하지 않는다.** 상태의 주인은 하나다
- **오프라인 쓰기를 하지 않는다.** 큐를 두면 세이브 충돌이 돌아온다

## 9. 구현 상태

웹앱을 `pokemon-card/web` 에 만들었다. 상점·팩·컬렉션·도감이 전부 서버 API 로 돈다.

### 로그인은 임시 문으로 뒀다

**구글 OAuth 는 아직 붙이지 않았다.** 계정 이름만 받아 `('test', 이름)` 신원으로 넣는
`POST /v1/auth/test` 를 열었고, `POKEPACKBAR_TEST_LOGIN=0` 으로 닫을 수 있다.

대신 1절의 신원 표는 그대로 만들었다. `users.apple_sub` 한 칸을
`identities(provider, subject, user_id, email)` 로 갈랐으므로, 구글을 붙일 때 같은 사용자에
줄이 하나 더 붙을 뿐 계정이 갈라지지 않는다. 검증 없는 `POST /v1/auth/apple` 은 지웠다.

### 서버에 더한 것

| 더한 것 | 비고 |
|---|---|
| `POST /v1/auth/test` · `GET /v1/auth/me` | 임시 로그인과 내가 누구인지 |
| `POST /v1/dev/grant` | **선물로 넣는다.** 사용량 표시를 거짓으로 만들지 않는다 |
| `GET /v1/files/{이름}.{판번호}.json` | 저장소가 없으면 서버가 직접 내준다. `POKEPACKBAR_STATIC_BASE` 를 주면 302 로 돌아간다 |
| `/v1/manifest` 의 `economy` | 환율·100원 칸·오리파 슬롯값 |
| `/v1/cards`·`/v1/state` 행의 `salePrice` | 판매가를 클라이언트가 계산하지 않게 한다 |
| 웹앱을 `/` 에 붙이기 | 빌드가 있으면 붙고, 없으면 API 만 돈다 |

명세와 다르게 간 곳이 하나 더 있다. **보너스 팩의 「확인」은 창 이름이 아니라 보상 키로
한다.** 같은 한도 창이 여러 번 찰 수 있어 창 이름만으로는 어느 보상인지 못 찾는다.
응답의 `grantKey` 를 그대로 돌려보낸다.

### 확인한 것

테스트 계정으로 지급 → 구매 → 50팩 개봉 → 잡카드 정리 → 오리파 뽑기까지 화면에서 돌렸다.
105종 500장에서 1,000원 이하 중복 85종 391장이 12만원에 정리됐고, 모든 종에 한 장씩 남았다.
서버 테스트는 75개가 통과한다.

### 남은 것

- **구글 OAuth.** 클라이언트 ID 가 나오면 1절대로 붙인다
- **서비스 워커 등록을 실제 브라우저에서 확인하지 못했다.** 파일은 같은 출처에서 올바른
  타입으로 나가는데, 검증에 쓴 미리보기 창이 등록을 막는다
- 카드 그림이 한 가지 크기뿐이라 상세 화면도 목록과 같은 것을 쓴다. 저장소에 `_hires` 가 없다
- 맥 앱은 아직 서버를 부르지 않는다

## 10. 화면을 맥 앱과 맞췄다

처음 만든 화면은 API 는 맞았지만 **구조가 달랐다.** 상점이 122개 팩을 한 목록에 늘어놓았고,
개봉이 카드를 한꺼번에 격자로 뒤집었고, 카드 칸마다 이름이 붙어 있었다. 두 클라이언트가
같은 상태를 보는데 화면이 다르면 오갈 때마다 다시 배워야 한다. 맥 앱의 구조로 되돌렸다.

### 치수와 글자를 그대로 가져왔다

`PopoverMetrics`·`CardGrid`·`Typography` 의 값을 CSS 변수로 옮겼다. 폭 440, 안쪽 여백 14,
탭 하나가 540, 컬렉션 격자 5열 74pt, 상점 팩 격자 3열 126pt, 글자는 13/14/15/17/20/24 이고
**13 아래로 내려가지 않는다.** 브라우저에서도 그 한 칸을 화면 가운데에 세운다.

색도 세만틱으로 맞췄다. `Color.secondary.opacity(0.06/0.07/0.12)` 를 칸 색 변수로 두고,
등급 색 24개는 `tierColor(_:)` 의 RGB 를 그대로 옮겼다. 라이트·다크는 시스템을 따라간다 —
맥 앱이 그렇게 동작한다.

### 되돌린 구조

| 화면 | 맥 앱의 구조 |
|---|---|
| 상점 | 갈래(일반팩·오리파) → **시대 목록** → 그 시대의 팩 격자 3열 → 팩 상세 → 카드 목록 |
| 팩 상세 | 뒤로 · 팩 그림과 이름 · 「이 팩의 카드 보기 n/N」 · 확률표 · 수량 스테퍼와 총액 |
| 개봉 | **한 장씩 크게.** 카드를 눌러 넘기고, 「한번에 열기」로 요약으로 건너뛴다 |
| 개봉 요약 | 제목 · 신규 수 · 이 팩의 총 시세 · 도감 완성 띠 · 팩 장수에 맞춘 격자 |
| 컬렉션 | 「무엇을 거를까」 줄과 「어떻게 볼까」 줄, 등급표 토글, 5열 격자 |
| 카드 칸 | 그림 위에 **등급 배지와 개수만.** 이름을 붙이지 않는다 |
| 카드 상세 | 자리를 통째로 내주고 230pt 카드, 이름 20pt, 등급·세트·보유, 시세, 도감 배지, 판매 |
| 도감 | 혜택 머리글 · 줄마다 이름·별·진행·카드 띠 5장·보상, 수령 가능한 줄은 테두리 |
| 오리파 | 박스 번호·교체 · 남은 슬롯과 등급별 수 · 5열 격자(가진 것은 흐리게 + 체크) · 뽑기 바 |

파괴적인 동작은 맥 앱처럼 **그 자리에서 확인을 받는다**(모달을 쓰지 않는다) — 오리파 뽑기와
박스 교체, 카드 판매, 잡카드 정리가 모두 같은 방식이다.

### 웹이라 다르게 둔 것

- **머리글 아랫줄**에 오늘 사용량과 한도 창 대신 누적 사용량·개봉·분해 수를 적는다.
  브라우저는 로그를 못 읽는다. 자리와 성격은 같다
- **좁은 화면에서는 열 수를 유지하고 칸만 줄인다.** 440 을 채울 수 없을 때 열이 바뀌면
  맥 앱과 다른 화면이 되고, 가로 스크롤은 쓰지 않는다
- 마우스를 올려 기울어지는 홀로 효과와 밑장을 끌어 들추는 동작은 넣지 않았다.
  맥 앱의 `HolographicCardView`·`RevealStack` 이 하는 일이고, 웹에서는 다음 장을 뒤에
  깔아 두는 것까지만 옮겼다

## 11. 표기 정책 전수조사

「5.6억원」을 지적받고 화면에 뜨는 숫자와 문구를 전부 앱과 대조했다. **웹에서 정책을 새로
만든 것이 문제였다.**

### 원은 세 자리 쉼표다

`WonFormatter` 의 주석이 이미 그것을 정해 두고 있었다 — 「토큰은 억·만으로 끊어 읽지만
(`TokenFormatter.readable`) 원은 쉼표를 쓴다. …「119만 6천원」보다 한눈에 들어온다.」

내가 만든 `wonText` 는 그것을 버리고 억·만으로 줄여 적었다. 지웠다. 이제 `money.ts` 는
앱의 세 함수를 그대로 옮긴 것이고, 각 함수 주석에 어느 Swift 함수인지 적어 두었다.

| 자리 | 쓰는 함수 | 나오는 것 |
|---|---|---|
| 쓸 수 있는 금액 · 팩값 · 판매가 · 환불 · 슬롯값 | `money` = `MarketEconomy.money` | `556,161,800원` |
| 카드 시세 · 컬렉션 가치 · 도감 총 가치 | `usdText` = `krw` + `WonFormatter.money` | `253,200원` |
| 누적 사용량 | `readableTokens` = `TokenFormatter.readable` | `3억 4212만 8891` |
| 도감 혜택 | `percent` = `L.percent` | `+0.2%` · `−5.5%` |
| 확률 공시 | `oddsText` | `54.7%` · `0.02%` |

**100원 단위로 버린다. 올림하지 않는다** — 버리는 쪽이라 「보이는 잔액 ≥ 보이는 가격」이면
실제로도 살 수 있다.

### 문구도 앱의 정본으로 되돌렸다

| 내가 쓴 것 | 앱의 정본 |
|---|---|
| 잔액 | **쓸 수 있는 금액** |
| 봉입 확률 / 보유 · 종수 | **등급별 확률** / **카드 한 장 기준** |
| 이 팩의 카드 보기 | **나올 수 있는 카드** |
| N개 사기 / 잔액이 모자랍니다 | **N개 구매** / **토큰이 부족해요** |
| 열기 | **뜯기** |
| 잡카드 정리 | **한번에 판매** |
| 등급별 | **등급별 수집 현황** |
| N번째 박스 / 박스 교체 | **N번 박스** / **새 박스로** |
| 되돌릴 수 없습니다 | **버릴까요?** · **뽑을까요?** |
| 지금 걸린 혜택 / N 수령 | **누적 혜택** / **완성 N / M** |
| 담긴 카드값 | **총 가치** |
| 개봉 완료 / 갓팩 | **개봉 결과** / **갓팩!** |
| 팩 할인 +5.5% | **팩 가격 −5.5%** (부호가 반대였다) |
| 획득순 / 중복 많은 순 | **최근 획득순** / **중복 많은순** |
| 수령함 | **수령 완료** |
| 즐겨찾기 | **대표 카드로** |
| 가진 팩이 없습니다 | **가진 팩이 없어요** |

말투도 앱을 따랐다 — 짧은 상태·빈 화면은 **해요체**, 결과와 이유를 설명하는 문장은
합니다체다. 앱이 그렇게 섞어 쓴다(「팔 중복이 없어요」 / 「한 장은 남습니다」).

판매 방식도 되돌렸다. **중복분을 한 번에 판다** — 장수를 고르는 스테퍼를 두었던 것을 없앴다.
남길 한 장은 규칙으로 정해져 있고, 나머지를 몇 장 팔지 고민할 이유가 없다.

## 12. 홀로 효과와 밑장 들추기

`HolographicCardView`·`RevealStack`·`TierGlow` 를 CSS·DOM 으로 옮겼다. 등급별 세기표
(`HoloProfile`·`TierGlow.strength`)와 고정 광원 광학(`HoloOptics`)은 값을 그대로 가져왔다.

### 홀로는 카드 상세에만 있다

처음에는 개봉과 오리파 뽑기에도 얹었는데 **앱의 정책이 아니다.** `HolographicCardView` 를
쓰는 곳은 `CardSpotlightView` 단 하나이고, 주석에 이유까지 적혀 있다 — 「확대 화면에서만
준다. 격자에서는 크기가 작아 각도가 읽히지 않고, 지나가는 커서마다 반응하면 산만하다.」

개봉과 뽑기는 **후광 + 카드 그림**뿐이다(`SpotlightCard`). 넘기는 중에는 카드가 계속 바뀌고
손이 카드 위를 지나므로, 커서마다 광택이 반응하면 산만하다. 그 자리에서 등급을 알리는 것은
후광이다.

오리파도 되돌렸다. 카드를 바로 보여 주고 있었는데 앱은 **가림막을 직접 밀어서 연다** —
카드는 처음부터 막 밑에 그려져 있고, 막이 밀린 만큼 그대로 드러난다. 막은 불투명한 주황이고
숨쉬는 크기가 1 아래로 내려가지 않는다. 반투명하면 카드가 비치고 줄어들면 가장자리가
삐져나온다 — 앱에서 둘 다 실제로 스포일러가 된 자리다. 후광도 밀어낸 만큼만 켜진다.

- **광택 다섯 겹.** 넓은 흰 반사광(screen) · 무지개 포일(color-dodge, 색상 회전으로 회절) ·
  좁은 광택 띠(color-dodge) · 반짝임(plus-lighter, 카드마다 고정 배치) · 가장자리 반사.
  SwiftUI 의 blendMode 를 CSS `mix-blend-mode` 로 옮긴 것이다
- **반사점은 회전 방향과 반대로 흐른다.** 마우스를 따라다니는 스포트라이트로 만들면 조명이
  손에 들려 함께 움직이는 것처럼 보여 물체감이 사라진다
- 등급이 올라갈 때만 포일(레어부터)과 반짝임이 붙는다. 커먼은 종이 광택뿐이다 —
  전부 무지개면 광택이 등급 신호로 작동하지 않는다
- **밑장이 실제로 깔려 있다.** 위 카드를 끌어 올리면 가려져 있던 만큼 드러나고, 62px 을
  넘기면 넘어간다. 덜 들췄으면 제자리로 돌아온다. 누르면 바로 넘어간다
- `prefers-reduced-motion` 이면 훑는 빛과 등장 애니메이션을 끈다

## 13. 웹에 맞춘 것

**앱과 똑같이 만들지 않는다.** 치수·글자·색·구조는 앱의 것을 쓰고, 담는 그릇만 웹의 관례를
따랐다.

| 앱 | 웹 |
|---|---|
| 폭 440 고정 | 화면을 채우고 640 까지 넓어진다. 그 이상 늘리면 한 줄이 너무 길다 |
| 탭 하나가 540 고정 | 남은 자리를 다 쓴다. 창을 키운 만큼 카드가 더 보인다 |
| 격자 5열 고정 | 칸 크기(74)를 지키고 **열 수는 자리에 맡긴다** |
| 상단 세그먼트 탭 | 넓은 화면은 그대로, **폰에서는 아래 탭 바** — 한 손으로 들면 위쪽 탭에 엄지가 닿지 않는다 |
| 머리글이 늘 위에 | 머리글과 탭을 `sticky` 로 붙여 둔다 |
| 마우스만 | 누르는 것을 40px 이상으로 키우고, 홀로 기울기와 밑장 들추기를 포인터 이벤트로 받아 손가락도 같게 동작한다 |
| — | `:focus-visible` 테두리를 둔다. 키보드로 다니면 이것이 없으면 길을 잃는다 |

아래 탭 바의 그림은 **SVG 로 그렸다.** SF Symbols 는 애플 기기의 시스템 글꼴에 들어 있어
브라우저가 못 불러오고, 그러면 네 탭이 똑같은 두부로 나온다(실제로 그렇게 나왔다).

## 14. 정책 전수조사

앞선 두 번의 지적(홀로 효과 자리, 금액 표기)이 **화면을 만들면서 정책을 추측한 결과**였다.
그래서 앱 UI 소스를 파트별로 전부 읽고 웹 구현과 하나하나 대조했다. **41곳이 달랐다.**

읽은 것: `PopoverView` · `SegmentedTabs` · `Typography` · `CardGrid` · `BackButton` ·
`CardShopView` · `PacksView` · `CardCollectionView` · `BulkSaleView` · `CardSpotlightView` ·
`DexView` · `OripaView` · `SettingsView` · `CardImageStore` · `HolographicCardView` ·
`LocalizationCards` · `WonFormatter` · `TokenFormatter`.

### 고친 것

| 파트 | 무엇이 달랐나 |
|---|---|
| 컬렉션 | **「보유한 카드만」기본값이 켜져 있었다.** 앱은 꺼짐 — 전체 목록에서 값순으로 봐야 무엇이 없는지 알 수 있다 |
| 컬렉션 | 필터·정렬·등급표 접힘·판매 임계값을 **기억하지 않았다**(`@AppStorage`) |
| 컬렉션 | 정렬 동률에서 시세를 다시 조회했다. 앱은 **들어온 자리**로 깬다 |
| 카드 그림 | 미보유가 옅기만 했다. 앱은 **흑백(saturation 0) + 0.35** |
| 카드 그림 | 모서리 반경이 고정값이었다. 앱은 **폭의 5%**. `object-fit` 도 `cover` → `contain` |
| 배지 | NEW 배지가 초록이었다. 앱은 **강조색** |
| 배지 | 개봉 요약·오리파·도감 띠가 컬렉션과 같은 배지를 썼다. 그 세 곳은 **그림 아래 등급 글자** |
| 별 | 난이도 별이 개수만큼만 떴다. 앱은 **항상 5칸**, 채운 별 주황 / 빈 별 회색 |
| 뒤로가기 | 채운 사각 박스였다. 앱은 **갈매기만**, 배경 없이 |
| 보상 | 선물과 보너스 팩을 한 줄로 합쳤다. 앱은 **따로**(선물 주황 · 보너스 초록), 각각 제목·본문·X |
| 개봉 | **「카드를 꺼내는 중」 화면이 없었다.** 그 화면이 갓팩을 **개봉 전에** 알린다 |
| 개봉 | 요약에 「한 개 더 뜯기」를 넣었다. 앱은 **확인만** |
| 개봉 | 도감 완성 띠 문구가 달랐다 — **「도감 완성!」** |
| 오리파 | 「한 번 더」를 넣었다. 앱은 **확인만** |
| 오리파 | 뽑기 버튼 라벨을 잔액에 따라 바꿨다. 앱은 **라벨 고정, disabled 로만** 막는다 |
| 오리파 | 안내가 「밀거나 눌러서 열어요」였다. 앱은 **「밀어서 확인」** |
| 오리파 | NEW 배지를 카드 위에 얹었다. 앱은 **카드 아래 정보 줄에** |
| 카드 상세 | 즐겨찾기가 글자 버튼이었다. 앱은 **★ 아이콘만**(가진 카드에만) |
| 카드 상세 | 도감 배지를 전부 늘어놓았다. 앱은 **미완성만, 남은 장수 적은 순, 최대 2개** + 진행도 |
| 카드 상세 | 추가금 안내가 달랐다 — **「판매 추가금 +N% 포함」** |
| 한번에 판매 | 임계값이 …10,000·30,000 이었다. 앱은 **1,000·3,000·5,000·7,000·10,000** |
| 한번에 판매 | 격자에 배지가 없었다. 앱은 **−N(팔릴 장수)** — 가진 장수가 아니라 사라질 장수 |
| 한번에 판매 | 버튼·칩 라벨과 결과 화면이 달랐다 |
| 팩 상세 | **세트 소개(`packBlurb`, 10개 세트)가 빠졌다.** 메타에 없는 시리즈를 넣고 있었다 |
| 도감 상세 | 「이 팩 사러 가기」를 늘 띄웠다. 앱은 **미완성일 때만** |
| 도감 상세 | 혜택 뜻을 적지 않았다. 앱은 상세에서 **보이는 글자로** 적는다 |
| 도감 상세 | 머리를 왼쪽에 붙였다. 앱은 가운데, 총 가치는 title·강조색 |
| 설정 | 제목이 왼쪽이었고 섹션 구분이 없었다. 앱은 **가운데 제목 + 테두리 카드** |

### 덤으로 잡은 결함

도감 줄을 `<button>` 으로 감쌌더니 안의 카드 칸도 버튼이라 **버튼 안 버튼**이 되어 브라우저가
DOM 을 재구성하고 줄 클릭이 아예 먹지 않았다. 앱도 같은 이유로 줄을 버튼으로 감싸지
않는다(주석에 적혀 있다). 이제 누를 수 없는 카드 칸은 `div` 로 그린다.
