# 팝오버를 닫아도 화면을 그대로 두기

팩을 뜯다가 팝오버를 닫으면 그 개봉이 통째로 사라진다. 다시 열면 상점 탭이고 돌아갈 길이 없다.
개봉만이 아니다 — 보던 카드, 걸어 둔 필터, 오리파 박스, 한번에 판매 화면이 전부 초기화된다.

**닫아도 보던 화면을 그대로 둔다.** 이 문서는 지금 왜 사라지는지와 그대로 두었을 때 무엇을
치르는지 정리한다.

## 1. 왜 사라지는가

원인이 둘이고, 둘 다 일부러 넣은 것이다.

```swift
func popoverDidClose(_ notification: Notification) {
    popover.contentViewController = nil   // 숨은 트리의 재레이아웃 비용을 없앤다
}

@objc private func togglePopover() {
    ...
    navigation.reset()      // 닫혔다 열리면 항상 Home 으로 (설정 화면 잔류 방지)
    buildPopoverContent()   // 열 때 호스팅 트리 생성
```

`@State` 는 화면 트리에 붙어 있으므로 트리를 버리면 함께 사라진다. 뜯던 장 번호, 무엇이
나왔는지, 오리파에서 뽑은 카드가 전부 거기 있다. 트리가 남아도 `reset()` 이 상점 탭으로
되돌리므로 어차피 팩 화면은 안 보인다.

곁가지로 `PopoverNavigation` 의 주석이 「닫아도 컨트롤러가 재사용되어 @State 가 유지된다」고
적고 있는데 사실이 아니다. 함께 고친다.

## 2. 비용이 실제로 얼마인가 — 재 봤다

트리를 버린 이유가 「숨은 트리의 재레이아웃 비용」이었으므로 그 값을 먼저 쟀다. 팝오버 트리를
살려 둔 채 사용량 갱신을 60회 흘리고 매번 레이아웃까지 돌린 결과다.

| 탭 | 창 상태 | 갱신 1회당 |
|---|---|---:|
| 컬렉션 | 숨김 | 4.89ms |
| 컬렉션 | 보임 | 5.49ms |
| 상점 | 숨김 | 1.87ms |
| 도감 | 숨김 | 2.17ms |

사용량 갱신은 기본 **120초에 한 번**이다. 가장 무거운 컬렉션 탭을 띄워 둔 채 닫아도
2분마다 5ms — **CPU 0.004%** 다. 숨겼을 때가 보였을 때보다 싸기도 하다(그리기를 건너뛴다).

**아끼려던 비용이 없다.** 트리를 들고 있는 쪽이 맞다.

## 3. 무엇을 바꾸는가

두 줄이다.

- `popoverDidClose` 에서 `contentViewController = nil` 을 지운다
- `togglePopover` 에서 `navigation.reset()` 과 매번 하던 `buildPopoverContent()` 를 지운다.
  트리는 처음 열 때 한 번 만든다

그러면 탭, 뜯던 장 번호, 개봉 결과, 오리파에서 뽑은 카드, 보던 카드 상세, 걸어 둔 세트·등급
필터, 한번에 판매 화면이 **전부** 그대로 남는다. 화면마다 따로 손댈 것이 없다.

덤으로 두 번째부터는 여는 속도가 빨라진다 — 열 때마다 트리를 새로 만들지 않는다.

### `reset()` 은 어떻게 하는가

부르는 곳이 없어지므로 지운다. 원래 목적이 「설정 화면에 갇히지 않게」였는데, 이제 설정을
보다 닫으면 다시 열었을 때도 설정이다. 그것이 「보던 화면을 그대로 둔다」와 같은 규칙이고,
설정에는 나가는 버튼이 있으므로 갇히지 않는다.

## 4. 맞물리는 곳 — 값 감추기

컬렉션 가치는 **아직 뒤집지 않은 카드만큼 빼서** 보여 준다. 값이 먼저 오르면 카드를 보기 전에
무엇이 나왔는지 알게 되기 때문이다. 그 감춤을 푸는 자리가 `RevealView.onDisappear` 인데,
지금은 팝오버를 닫을 때 트리가 죽으면서 그것이 불렸다.

트리를 들고 있으면 **닫아도 안 불린다.** 그게 맞다 — 개봉이 안 끝났는데 값이 오르면 안 된다.
바꿀 코드는 없고, 「닫았다 열어도 값이 안 올라 있다」를 테스트로 잠근다.

## 5. 확인할 것 하나 — 숨은 애니메이션

오리파 가림막은 숨쉬듯 커졌다 작아지는 반복 애니메이션을 돈다. 트리를 들고 있으면 팝오버를
닫아도 그 애니메이션이 계속 돌 수 있다. 2절의 측정은 사용량 갱신 비용만 잰 것이라 이건 안 잡힌다.

구현한 뒤 **오리파 뽑기 화면을 띄운 채 팝오버를 닫고 CPU 를 본다.** 계속 돈다면 창이 보일
때만 애니메이션을 걸도록 막는다(`.onAppear`/`.onDisappear` 대신 창 표시 상태를 보는 쪽).

## 6. 테스트로 잠글 것

- 팝오버를 닫았다 열어도 탭이 그대로다
- 닫았다 열어도 뜯던 장 번호가 그대로다
- 개봉 도중에 닫았다 열어도 컬렉션 가치가 안 올라 있다
- 닫을 때 호스팅 컨트롤러를 버리지 않는다 (소스 검사 — 되돌아가면 전부 되돌아간다)
- 열 때 `reset()` 을 부르지 않는다 (소스 검사)

앞의 셋은 화면 상태라 단위 테스트로 직접 재기 어렵다. 호스팅 컨트롤러를 만들고 버리는 것을
흉내 내는 대신, **버리지 않는다는 사실 자체**를 소스에서 검사하는 편이 실제 보장에 가깝다.

## 7. 남는 한계

**탭을 옮기면 개봉은 여전히 사라진다.** 탭을 바꾸면 그 탭의 화면이 트리에서 빠지므로 `@State`
가 죽는다. 팩을 뜯다가 컬렉션을 보러 갔다 오면 뜯던 자리가 없다.

고치려면 개봉 상태를 화면 밖(앱이 들고 있는 객체)으로 빼야 하는데, 그건 이번 변경과 성격이
다르고 훨씬 크다. 팝오버를 닫는 것은 흔하고 뜯는 도중에 탭을 옮기는 것은 드무니 흔한 쪽만
먼저 고친다. 필요해지면 그때 뺀다.

**앱을 껐다 켜면 사라진다.** 메모리에만 있기 때문이다. 카드와 잔액은 이미 반영돼 있으므로
잃는 것은 연출과 요약뿐이다.
